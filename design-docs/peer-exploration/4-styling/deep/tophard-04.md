## jedi-statusline
https://github.com/tanerincode/jedi-statusline (20 stars). Read: `scripts/statusline.py` (360 lines), README.

1. Colour source is mixed. By state/tier: `RANKS` table (`statusline.py:62-76`) gives each rank a 256 index (Youngling 250, Padawan 39, ... Jedi Knight 82, Master 208, Guardian 220, Grand Master 135, Force Ghost 159, Chosen One 229). That `col` paints the rank title, the XP bar fill (`bar(frac,12,'▰','▱',col)`, l.327), the kyber crystals and the session name. `DARK_TIERS` (l.144) override it by alignment: <=-80 124, <=-50 196, <=-20 202. By threshold: context heat `GREEN 82 <50%, GOLD 220 <80%, RED 196` (l.336), colouring both the bar and the "N% hyperdrive / ⚠ overheating" text. Fixed per segment: model always `SKY 39` (l.339), branch `GREEN`, cost `GOLD` (`₡`), effort/epithet/labels/separators `DIM 244`, XP count `CREAM 230`, "+N XP" ticker `GREEN` bold, promotion banner `GOLD` bold, alignment marker 255 bold, slider track 244.
2. Themes: not present. Colours are hardcoded constants (`DIM, CREAM, GOLD, RED, GREEN, SKY`, l.59). `config.json` exists (l.37) but the script only defines `config()`, and the README names no colour keys.
3. Colour spec/depth: 256-index only, `\033[38;5;Nm` (`c()`, l.57), plus bold `\033[1m`. Truecolor RGB tuples in `RANKS` are used only for the iTerm2 sequences, not the line. No depth detection, no NO_COLOR handling found.
4. Fill: foreground-only text on the terminal's own background. No background fills (`48;` never appears).
5. Separators: plain text. `"│ "` and `" · "` in DIM (l.344), double spaces between blocks. No powerline.
6. Neighbours: told apart only by hue per fixed role plus DIM separators. No alternating or stepping.
7. Light/dark adaptation: not present. The palette (244 grey, 230 cream) assumes a dark terminal; no contrast computation.
8. Glyphs: Unicode block and shape glyphs, no Nerd Font and no ASCII fallback: `▰▱`, `▮▯`, `◆◇` kyber, `₡`, `⚠`, `●`, `▸◂`, `-` slider. `SABER` frames `▏▎▍▌▋▊▉█` (l.172) are defined, and the frame counter advances, but `line1`/`line2` never print `SABER`, so the lightsaber animation shown in the docstring is not drawn in this file (unverified why; README mentions an "animated" line). Emoji not in this script; the scanner's emoji count is probably from `bin/jedi`/docs.
9. Other: iTerm2 integration writes tab/background colour from the rank RGB (`\033]6;1;bg;red;brightness;..`), plus a badge via `SetBadgeFormat` and tab title, straight to `/dev/tty` (l.235-253). A "promoted" 20 s banner flash in gold. Live "+N XP" ticker for 8 s after a gain. README links `docs/hero.svg` and `docs/promotion.svg` screenshots, regenerated by `docs/render.py` (not read). Alignment slider `dark ---●▸--- light` shows drift direction with an arrow.
10. Customisation: no theme surface. Env `JEDI_DIR` moves state; `JEDI_REVIEW`, `JEDI_REVIEW_MODEL` affect the judge, not colour. State in `~/.claude/jedi-statusline/state.json`. Ranks are set by CLI (`jedi advance|promote|pin|demote`) and so indirectly drive the colour. Plugin install with a `/jedi-statusline:setup` skill.

## yefanfan
https://github.com/yefanfan123/yefanfan (20 stars). Read: `mcp-plugin/statusline.js` (221 lines), `vibe-english.sh` (grep for colour only).

1. Colour source: none. `statusline.js:214-219` writes two lines of plain text with no escape codes at all. Everything is emoji, a kaomoji face and Unicode dots. The face and energy bar change by state (energy >=80 `(^_^)`, >=50 `(·_·)`, >=20 `(o_o)`, >=1 `(u_u)`, else `(x_x)`; bar `●` x filled, `○` x empty, l.113-124), but that is glyph state, not colour.
2. Themes: not present.
3. Colour spec/depth: not present (no ANSI emitted by the statusline). NO_COLOR: not present. The 16-colour codes the scanner saw are in `vibe-english.sh:11-17` (`\033[0;36m` cyan, `1;33` yellow, `0;32` green, `0;35` magenta, bold, dim), which colour that installer script's own output, not the status line.
4. Fill: neither; plain default-coloured text.
5. Separators: plain ` | ` between blocks (l.214, 217).
6. Neighbours: separated by ` | ` and emoji prefixes only: pet emoji, `⚡`, `💬`, `📖`, `📚`.
7. Light/dark adaptation: not present; inherits the terminal's default text colour, so it is readable on both.
8. Glyphs: emoji-heavy. Pet emoji chosen from the `~/.claude.json` companion name via `emojiMap` (l.81-97, default 🍄); `⚡` energy, `💬` Chinese translation, `📖` word hints, `📚` count. No Nerd Font, no ASCII mode.
9. Other: it is a language-learning pet (English sentences with Chinese translation, optional macOS TTS via `speak-lesson.js` spawned detached), not a styling-focused project. Content rotates every 3 minutes (`rotateInterval`, l.177). Tech-stack detection from the cwd filenames picks the sentence pool (l.146-169).
10. Customisation: no styling options. Configured through the `statusLine` entry in settings.json; content from `sentences.json`; state in `~/.vibe-english/pet-state.json`. No colour env vars or flags.
