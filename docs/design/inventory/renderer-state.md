# What a renderer replacement can reconstruct

This inventory describes the Node renderer before the peer-renderer migration. A renderer restart keeps the host alive. A host restart additionally depends on which writes reached storage. A switch between named renderers currently selects another profile. These are three different boundaries.

## Session and config

| Retained value | Owner, writer and cadence today | Reconstruction and visible loss |
| --- | --- | --- |
| Hook input, hints, observed world, token counts and sample times | The host collector updates session facts on observations. The host usage store appends a sample when the transcript stamp changes. | Start supplies live contexts and worlds. Token rate and sparkline derive from the sample ring. Losing a previous observation changes the rate; replacing only the renderer preserves the host ring. [Usage store](../../../src/daemon/cache/session-usage-store.ts) · [Payload](../../../src/renderer/render-payload.ts) |
| Committed settings, disclosures, confirmation arms, pointer state and click errors | Session writes come from verbs, idle expiry and error handling. Each turn drains changed sessions to the host’s profile. Request activity can move a session in recency order without changing its contents. | The host supplies the filtered picks and their order on boot. An ordinary open menu and armed confirmation survive. Edit keys are filtered. The in-memory revision counter is regenerated during construction, so its numeric value cannot identify the same revision across peers. [SessionState](../../../src/renderer/session-state.ts) · [Persistence filter](../../../src/renderer-interface/stored-state.ts) · [Host boot test](../../../test/unit/held-stores.test.ts) |
| Committed settings undo and redo | A click journal records changed settings and layer contents in the session’s bounded past and future. The host holds the outliving steps alongside the picks. | Restore both stacks from the profile. The current file or pick alone cannot supply the previous value when Undo is clicked. [SettingsHistory](../../../src/renderer/settings-history.ts) · [Storage tests](../../../test/unit/stored-outlives.test.ts) |
| Menu Back destinations | Navigating clicks commit visits between menu views. Back moves a cursor and checks each destination against the current gate. The renderer constructs a new NavigationHistory on boot. | A switch needs the visits and cursor or the ordered transitions that produced them. An open menu alone cannot recover which page Back should show. [NavigationHistory](../../../src/renderer/navigation-history.ts) · [Back tests](../../../test/navigation-history.test.ts) |
| Open edit | EditTransactions starts a draft at a config origin and base snapshot. Edits update a sparse set of writes and clears, staged file contents, private undo/redo and navigation. Discovery supplies the latest config for conflict checks. Save or Cancel ends the edit. | Preserve the active draft, its base and histories for a peer to preview, undo, cancel or save the same work. Derive the normalized config and counts again. While editing, pointer and click-error records bypass the draft. Losing the draft loses unsaved changes even if the committed profile survives. [Edit transactions](../../../src/renderer/edit-transaction.ts) · [Draft projections](../../../src/renderer/setting-drafts.ts) · [Edit tests](../../../test/unit/edit-transaction.test.ts) |
| Config selection, variable stores, compiled templates and action gates | Config offers and source results originate in the host. Opening or reloading a view builds or shares compiled config and derived MobX nodes. A rejected config can leave the last good input selected. | Restore the selected input **and** the later rejected offer to reproduce the working bar with its diagnostic. Rebuild compiled objects, pins, reactions and derived values locally. To reproduce a source’s age or error timestamp, use the stamped input that changed it. [RenderCache](../../../src/renderer/render-cache.ts) · [SourceRegistry](../../../src/var-system/sources.ts) · [Hot-reload tests](../../../test/daemon-render-cache.test.ts) |

A document source can retain an earlier successful read while a later malformed observation waits for its settle deadline. A new observation can cancel that failure. To reproduce this interval, keep the last successfully parsed document, whether it was a real read, the outstanding observation and its deadline, or replay those observations with the original stamps. A peer that starts with only the malformed bytes can show a warning while the live bar still shows the document. [Document publisher](../../../src/var-system/sources.ts) · [Torn-write tests](../../../test/var-sources.test.ts)

## Draws, deliveries and effects

| Retained value | Owner, writer and cadence today | Reconstruction and visible loss |
| --- | --- | --- |
| Accepted layout and diagnostics | A draw creates a candidate. A successful host delivery receipt can advance the renderer’s accepted record for that session’s request or feed surface. Retired view targets and older same-surface receipts cannot replace it. View retirement also changes which layout and copy data remain available. | Rebuild the surface’s accepted predecessor at its width, config, preset and revision, including previously drawn rows, rule choices, diagnostics and copy targets. A dropped draw cannot establish a new baseline. Without the predecessor a pending cell can change width or a copy link can lose its text. [PresentedFrames](../../../src/renderer/presented-frames.ts) · [Frame memory](../../../src/render/frame-memory.ts) · [Delivery tests](../../../test/renderer-answer.test.ts) |
| Motion and menu idle | The newest accepted draw across request and feed advances shared session motion and menu observations. Clicks reset the idle clock and due turns can expire it. A late receipt for the other surface can advance that surface’s layout while preserving the newer session timeline. | Restore the timeline anchor/rate, effect start and placement history, row effect state and idle observations via ordered inputs and receipts. Loss restarts effects or changes when a menu flashes or closes. An object identity, function or rich-js instance in one heap cannot identify a checkpoint in another. [Effects](../../../src/render/effect.ts) · [MenuIdle](../../../src/renderer/menu-idle.ts) · [Pending draws](../../../test/pending-draw.test.ts) |
| Feed schedule and displayed rate | The host holds viewer counts, visibility, pointer observations and the feed history for the lifetime of the subscription. Each attempt updates the previous content, the changed-draw ticks for each surface and the next scheduled draw. The displayed rate counts changes in the last second. | A replacement resumes that history, including draws a subscriber declined. An outstanding retry keeps its original deadline. A new subscription starts with an empty rate history. Operational counters and histograms start with the new renderer. [Host feed history](../../../src/daemon/host-feed-history.ts) · [Feeds](../../../src/renderer/feeds.ts) · [Rate tests](../../../test/unit/feeds.test.ts) |
| Outstanding clicks, writes, presents and wakes | The host orders turns, authorizes effects and reports outcomes. The renderer retains candidate deliveries, config-write continuations, owed act IDs and deadline callbacks until settlement or retirement. The host scopes receipts to the originating generation. | Preserve the displayed origin and the host outcome of a live operation when switching. Apply that outcome once. An offline replay consumes recorded outcomes without an executor. Reconstruct semantic deadlines from the original stamps; live timers, mailbox callbacks, effect IDs and subscription handles belong to their generation. [ConfigWrites](../../../src/renderer/config-writes.ts) · [TurnTime](../../../src/renderer/turn-time.ts) · [Late receipt tests](../../../test/unit/renderer-process.test.ts) |

## Inputs for a comparison

The existing [recording replay](../../../src/renderer/replay.ts) provides a reference for deterministic turns when a capture includes construction and the required ordered inputs. For example, layout insertion currently mints a placement ID inside the verb. Re-executing that gesture can mint a different ID even with the same timestamps. The peer determinism work (.5uc.3ft) must make the ID reproducible from the input or carry the committed ID. [Layout insertion](../../../src/renderer/verbs/index.ts) Start both peers from equivalent inputs and offer the same requests, config selections, source observations, gestures, time readings, draws and delivery outcomes. This also reconstructs inputs that are easy to overlook when taking a snapshot, such as a menu idle deadline and a previous feed frame that changed the displayed rate.

A compact checkpoint must reproduce that history's effect on the chosen surface. Exercise it at a narrow width with a wrapped cell pending mid-transition. Deliver a newer request frame and an older feed receipt out of order. Compare whole frames, including links and hit targets, against full replay. A comparison must leave the live surface’s accepted predecessor and the host’s outstanding operations untouched.
